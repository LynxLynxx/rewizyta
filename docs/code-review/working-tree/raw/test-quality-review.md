## Repository / Service Test Quality

- `clients_repository_impl_test.dart`: **Pass.** `NativeDatabase.memory()` per
  CLAUDE.md convention, `setUp`/`tearDown` close the db, fixtures from
  `helpers/fixtures.dart`. Covers upsert+outbox-in-one-transaction, a full
  round-trip of every new `Client` column (phone, addressLine, town, postalCode,
  lat, lng, note, contactId), soft-delete-hides-from-watchAll, delete queued as
  `OutboxOp.delete`, outbox replacement on a second write to the same row, and
  UTC normalization of local timestamps. This is the template the rest of the
  suite follows.
- `appointments_repository_impl_test.dart`, `catalog_repositories_impl_test.dart`,
  `devices_repository_impl_test.dart`, `equipment_repository_impl_test.dart`,
  `reminders_repository_impl_test.dart`, `visit_repositories_impl_test.dart`,
  `key_value_repositories_impl_test.dart`: **Pass.** Same pattern throughout:
  in-memory drift db, real fixtures, assertions on both the decoded domain
  object and the raw stored/outbox row. Good edge-case discipline — e.g.
  `watchBetween`'s `[from, to)` boundary and timezone-insensitivity,
  `AppointmentStatus.noShow` round-tripping as `no_show` down to the raw SQL
  column, the `CHECK (cycle_months > 0)` / `CHECK (count > 0)` constraints,
  the trade `template_key` uniqueness ("a default can be copied only once"),
  `lastDoneAt` ignoring deleted visits/unticked items, and visit-item
  restore-by-reupsert. `AppSettingsRepositoryImpl.watch` is tested with a live
  subscription asserting the full emitted sequence (`[null, 'dark', null]`),
  not just a single value.
- `app_database_test.dart`: **Pass.** Exercises deferred-FK ordering within a
  transaction, rollback on a dangling reference, and cascade/set-null behavior
  on client deletion — these are cross-cutting schema guarantees that would be
  easy to regress silently; good that they are pinned down here.
- `dto_test.dart`: **Pass.** One parametrized-by-hand round-trip
  (`fromDomain → JSON → wire → fromJson → toDomain`) per synced entity, plus
  targeted Postgres-shape tests (snake_case keys, `user_id` injection,
  timestamptz-with-offset decoding to UTC, snake_case enum decoding, and an
  unknown enum value failing loudly via `throwsArgumentError`). This single
  file is effectively the equality/serialization test for every new model in
  `rewizyta_models` that this change-set adds (`Appointment`, `ServiceType`,
  `Trade`, `Device`, `Equipment`, `Reminder`, `Visit`, `VisitItem`) — the models
  themselves have no dedicated `_test.dart`, consistent with the pre-existing
  convention (`due_date_test.dart` only tests the pure `nextDue` function, not
  the hand-written `copyWith`/`Equatable` boilerplate), so this is not flagged
  as a gap.
- `clients_service_impl_test.dart`: **Mostly pass, one gap.** Correct mocktail
  usage (`class MockClientsRepository() extends Mock implements
  ClientsRepository;` — primary-constructor syntax per CLAUDE.md),
  `registerFallbackValue` for the `Client` used in `any()`, `verify`/
  `captureAny` used meaningfully (asserts the *captured* client's
  `deletedAt`, not just that `upsert` was called). Good coverage of
  `saveClient`: creation with a generated id and stamped timestamps, name/
  phone validation errors, and the update-path rules (keeps `createdAt` and
  `contactId`, keeps coordinates only when the address is unchanged, drops
  them when it changes). `deleteClient` and the not-found path of `getClient`
  are both tested. The gap: `watchClients()` — a real `ClientsService` method —
  has no test at all (0 call sites of `repository.watchAll()` or
  `service.watchClients()` in the file), confirmed by the coverage run (line 17
  uncovered). CLAUDE.md is explicit that "every service method ... gets a
  test"; a one-line pass-through is still a public contract (e.g. that it
  returns the repository's stream unchanged, not a filtered/mapped one) and
  a regression here (e.g. accidentally filtering soft-deleted clients, or
  swapping `watchAll()` for something else) would not be caught.

## Anti-Patterns Found

None of the VGV/anti-pattern list (tautological assertions, mocking the class
under test, no-assertion tests, implementation mirroring, over-verification)
were found in the reviewed test files. Assertions are behavioral (decoded
objects, raw SQL columns, emitted stream sequences, thrown exception types/
fields), not implementation-shaped.

## Gaps (not anti-patterns, but real coverage holes)

1. **`ClientsServiceImpl.watchClients()` has no test**
   (`packages/rewizyta_services/test/clients_service_impl_test.dart`). Confirmed
   by coverage (line 17 of `clients_service_impl.dart` uncovered). Every other
   method on the same interface is tested; this one is a silent gap.

2. **Money-in-grosze fields are never round-tripped with a non-null value.**
   `ServiceType.defaultPriceGrosze` (`packages/rewizyta_models/lib/src/catalog/service_type.dart`)
   and `Visit.priceGrosze` (`packages/rewizyta_models/lib/src/visit/visit.dart`)
   are both `int?` money fields per CLAUDE.md rule 8 ("Money is an integer in
   grosze"). `helpers/fixtures.dart`'s `serviceType()` and `visit()` builders
   don't expose a parameter for either field, so no test in
   `dto_test.dart`, `catalog_repositories_impl_test.dart` or
   `visit_repositories_impl_test.dart` ever constructs one with a non-null
   price. The JSON (de)serialization for both is a plain `(json['...'] as
   num?)?.toInt()` generated by `json_serializable`, so the risk of a silent
   int/double or scaling bug is real and currently undetected by any test —
   exactly the kind of field this project singles out as a hard rule.

3. **`ClientsServiceImpl.getClient` has no direct happy-path test.** The
   not-found path (`throwsA(isA<ClientNotFoundException>())`) is tested
   directly; the success path is only exercised indirectly, as a side effect
   of the `saveClient` "updating" tests reading back `existing`. A direct
   `test('getClient returns the client found', ...)` would make the
   specification explicit and would not depend on `saveClient`'s unrelated
   logic to catch a regression in `getClient` itself.

## Recommendations

1. Add a test for `ClientsServiceImpl.watchClients()` asserting it forwards
   `_repository.watchAll()` unchanged (e.g. stub a stream on the mock, assert
   the emitted list is identical).
2. Add a non-null `defaultPriceGrosze` case to `ServiceTypeDto`'s round trip
   (extend `fixtures.dart`'s `serviceType()` with an optional parameter) and a
   non-null `priceGrosze` case for `Visit`/`VisitDto`, so the money-in-grosze
   invariant is actually pinned down by a test, not just by convention.
3. Add a direct `getClient` happy-path test to `clients_service_impl_test.dart`
   for symmetry with the existing not-found test.

## Verdict

Fix 1 issue before merging (the untested `watchClients()` method — a plain
violation of this repo's explicit "every service method gets a test" rule).
The two Suggestion-level items (money-field round-trip, direct `getClient`
happy path) are worth doing but are not blocking: both paths are exercised
indirectly today and carry low risk given the fields' trivial, transform-free
mapping. Everything else reviewed — the repository layer's 100% coverage on
every touched impl/mapping/DTO file, the DTO round-trip and Postgres-shape
tests, the constraint/edge-case discipline, and the mocktail usage in the
services test — meets this project's bar.
